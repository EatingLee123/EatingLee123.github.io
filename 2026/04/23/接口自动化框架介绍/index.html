接口自动化框架介绍

接口自动化框架

基于 pytest + requests + openpyxl + PyYAML + pymysql + allure 的数据驱动接口自动化测试框架。

框架采用 Excel 管理真实参数 + YAML 管理接口模板与断言规则 的模式，执行时自动完成变量替换、接口关联和多维断言。

核心能力

  • 数据驱动：Excel 管理用例输入与预期，YAML 管理请求模板与断言规则。
  • 接口关联：支持通过 extract 自动提取响应字段并注入全局变量。
  • 统一断言：支持状态码、JSONPath、数据库行数断言，入口统一。
  • 流程编排：支持将“每行一个步骤”的 Excel 数据组装为流程场景执行。
  • 报告输出：默认输出日志，并集成 Allure 结果与 HTML 报告。

数据驱动设计

Excel：存真实值与 YAML 路径

示例：Testdata/login_data.xlsx 的 login sheet 字段可包含：

  • case_name
  • yaml_path
  • username
  • password
  • expected_status
  • db_expected_count

YAML：存请求模板与断言规则

示例：Testdata/Transaction/login.yaml

变量替换规则

YAML 中 ${username}、${password}、${expected_status} 等占位符，会在执行时由 Excel 当前行真实值替换。

接口关联机制

1) 在 YAML 声明提取规则

表示从当前响应提取 $.data.orderId，写入全局变量 accept_order_id。

2) 在下游接口直接使用

执行时自动从 GlobalData 注入最新值。

3) 全局变量存储

  • 文件：Common/global_data.py
  • 类名：GlobalData
  • 用途：跨步骤共享 orderId/token/policyNo 等动态数据

断言能力

支持以下断言类型：

  • status_code：HTTP 状态码断言（必填）
  • json_path：响应体字段断言（可选，支持多条）
  • db：数据库行数断言（可选，enabled: true 时执行）

统一断言封装位于 Common/assertions.py：

  • assert_response_by_rule(response, assert_rule, expected_status=None)
  • safe_response_json(response, default=None)

当前 Testcase/test_login_api.py、Testcase/test_mcp_three_api_flow.py 已接入。

MCP 流程数据封装

Common/utils.py 提供：

  • build_flow_cases(excel_rows, scenario_key="scenario_id", step_key="step_no")

可将 Excel 的平铺步骤数据组装为按步骤排序的流程场景结构，减少流程用例重复代码。

配置说明

配置文件：Config/settings.py

  • ENV_CONFIG.base_url：接口环境地址
  • ENV_CONFIG.mcp_base_url：MCP 接口环境地址
  • DB_CONFIG：数据库连接信息
  • DB_CONFIG_SCORE：成绩校验数据库连接
  • ALLURE_RESULT_DIR：Allure 结果目录（report/result）
  • ALLURE_HTML_DIR：Allure HTML 目录（report/html）

默认重试参数在 pytest.ini 的 addopts 中：

  • --reruns 5 --reruns-delay 2

conftest.py 作用

conftest.py 是 pytest 全局扩展入口，会被自动发现并加载。

本项目中主要负责：

  • pytest_sessionstart：创建输出目录、清理 report/result、写入环境信息、记录启动日志
  • pytest_sessionfinish：记录结束日志、提示报告路径与查看命令
  • setup_and_teardown (autouse=True)：每条用例自动前后置，失败时附加错误信息到 Allure

可简单理解为：

  • Testcase/test_*.py 负责测试逻辑
  • conftest.py 负责全局生命周期和公共初始化

团队规范（推荐）

1) YAML 命名规范

  • 每个接口一个 YAML，放在 Testdata/Transaction
  • 文件名建议 模块_接口_场景.yaml，如 user_login_success.yaml
  • 统一小写下划线，禁止中文文件名与空格

2) Excel 字段规范

  • 一个业务模块一个 Excel，例如 login_data.xlsx
  • 一个 sheet 对应一组同类型场景
  • 必填列：case_name、yaml_path
  • 建议列：${变量} 对应真实值列和预期结果列（如 expected_status）
  • yaml_path 使用相对项目根路径，如 Testdata/Transaction/login.yaml

3) YAML 字段规范

  • 建议固定结构：case_name、method、url、headers、payload、assert
  • payload 动态值统一使用 ${变量名}，且需在 Excel 中存在同名列
  • assert.status_code 必填
  • assert.json_path、assert.db 可选，不需要时写空列表或 enabled: false

4) 断言编写规范

  • 每个用例优先保证 status_code 断言
  • JSONPath 建议使用 $.a.b[0].c 风格
  • 数据库断言默认 enabled: false，启用时 SQL 需可重复执行且结果稳定
  • 单用例关键断言建议不超过 5 条，便于排障

5) 新增用例流程

  1. 在 Testdata/Transaction 新建接口 YAML 模板
  2. 在 Excel 对应 sheet 增加一行用例数据
  3. 执行 pytest -k 关键字 本地验证
  4. 生成 Allure 报告并确认展示正常
